# 记忆模块


1. 长期记忆：mem0 + Brain.mem
Brain 构造时可传入 memory 或 memory_config；若提供 memory_config，会懒加载 mem0.Memory.from_config，挂到 self.mem。




2. 单次运行内的「工作记忆」：History（AgentState.history）
多步 agent 循环里用 History 存 OpenAI 格式的消息列表，并在过长时做 压缩（_compact_history）、大块输出的 decay 等，这是 当前任务多步推理的上下文记忆，不是跨会话向量库。




短期记忆的记忆压缩
短期记忆相关的「压缩」在 BaseAgent 里主要分两块：自动用 LLM 做对话摘要（Auto Compact），以及 大块输出落盘替换（History Decay）。和「上下文窗口」强相关的是前者。


1. 何时触发（自动）
每步执行完，在 update_state 里：先把本步结果转成消息追加进 state.history，再做 decay 检查，最后判断是否要做 compact：

```python

        # History decay check (decay old large outputs to files)
        if self.decay_enabled:
            self._check_and_decay()


        # Auto compact check
        if self.auto_compact_enabled and _should_compact(self.state.history):
            self.state.history = await self._compact_history(self.state.history)
```

2. 是否该压缩：按 token 占上下文比例
```python

配置（默认值）：
    # Auto compact configuration
    auto_compact_enabled: bool = True           # Enable/disable auto compact
    auto_compact_threshold: float = 0.92        # Trigger threshold (92% of context window)
    auto_compact_keep_recent: int = 10          # Keep recent N messages as-is
    default_context_window: int = 128000        # Default context window size (128K tokens)
    compact_model: Optional[str] = None         # Model for compaction, None uses agent.llm

    逻辑（_should_compact）：

    关闭 auto_compact → 不压。

    历史条数 ≤ auto_compact_keep_recent → 不压（避免没东西可「旧消息」）。

    用 num_tokens_from_messages 统计当前 history 的 token；上下文上限来自 get_model_context_window(model_name)（取不到则用 default_context_window）。

    若 current_tokens >= context_limit * auto_compact_threshold → 触发压缩。
```


3. 怎么压：旧段摘要 + 最近 N 条原样（_compact_history）

切分：除最近 auto_compact_keep_recent 条外，前面全是「旧消息」。

系统消息：旧段里 role == "system" 的整条 保留，不参与摘要。

待摘要：旧段里非 system 的消息，用 _build_compact_prompt 拼成一段文本；每条 content 超过 2000 字符会先截断 再送给摘要模型，避免摘要请求本身过大。

调用模型：专用 compact_model 或当前 self.llm，走 generate 或 chat，system 里固定一段「你是对话摘要器…保留任务、步骤、代码/决策、问题与解决」的说明。

拼新 History：


先放 保留的旧 system；

再放 一条新 system，内容为 [Conversation History Summary]\n{摘要}\n[End of Summary - Recent messages follow]；

再依次追加 最近 N 条原消息。

失败（无 LLM、异常）则 返回原 history，不改动。


4. 手动压缩
compact_now(state=None) 会直接对指定（或当前）state.history 调用 _compact_history，不单独再做 token 阈值判断（阈值只在 update_state 里自动路径使用）。


5. 和「Decay」的区别（别混在一起）
History Decay 针对 单条消息体积 ≥ decay_min_size（默认 100KB） 的内容：打上 _decay_meta，过 decay_ttl_steps 步后把正文 写到 ~/.minion/decay-cache，消息里改成 指向文件的短说明。这是 省位子的另一种手段，不是用 LLM 把整段历史压成一段摘要。


一句话：短期记忆的「压缩」核心是 当历史 token 接近模型上下文上限时，把「除最近 10 条外的旧对话」交给 LLM 压成一条 system 摘要，并保留旧里的 system 与最近 N 条原文；大块输出另有一条 落盘 decay 路径。
