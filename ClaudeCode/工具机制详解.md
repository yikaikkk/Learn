# Claude Code 工具机制分析

## 1. 工具机制概述

Claude Code 实现了一套完整的工具使用机制，允许模型通过工具调用来执行各种操作，如文件读写、代码搜索、命令执行等。这种机制使 Claude Code 能够与外部环境交互，执行复杂的任务，并为用户提供更丰富的功能。

### 1.1 核心概念

- **Tool Use**：模型发出的工具使用请求，包含工具名称和参数
- **Tool Result**：工具执行的结果，返回给模型
- **Tool**：具体的工具实现，包含执行逻辑、参数验证、权限检查等
- **Tool Use Context**：工具执行的上下文，包含环境信息、状态管理等

## 2. 工具消息结构

### 2.1 工具使用消息 (Tool Use Message)

工具使用消息由模型生成，包含以下关键信息：

- `tool_use_id`：工具使用的唯一标识符
- `name`：工具名称
- `input`：工具参数（根据工具的输入模式定义）

示例：
```typescript
{
  "type": "tool_use",
  "id": "tool_use_123",
  "name": "FileReadTool",
  "input": {
    "file_path": "src/index.ts",
    "offset": 1,
    "limit": 100
  }
}
```

### 2.2 工具结果消息 (Tool Result Message)

工具结果消息由系统生成，包含以下关键信息：

- `tool_use_id`：对应的工具使用ID
- `content`：工具执行的结果
- `is_error`：是否为错误结果

示例：
```typescript
{
  "type": "tool_result",
  "tool_use_id": "tool_use_123",
  "content": "// Source code content...",
  "is_error": false
}
```

## 3. 工具执行流程

### 3.1 工具执行的完整流程

1. **模型生成工具使用消息**：模型分析用户请求，生成工具使用消息
2. **消息处理**：系统接收并处理工具使用消息
3. **工具查找**：根据工具名称查找对应的工具实现
4. **参数验证**：验证工具参数是否符合要求
5. **权限检查**：检查用户是否有权限执行该工具
6. **工具执行**：调用工具的 `call` 方法执行具体操作
7. **结果处理**：处理工具执行结果，生成工具结果消息
8. **结果返回**：将工具结果消息返回给模型
9. **模型处理**：模型分析工具结果，生成下一步响应

```typescript
export function isToolUseRequestMessage(
  message: Message,  // 消息对象
): message is ToolUseRequestMessage {
  return (
    message.type === 'assistant' &&  // 检查消息类型是否为assistant
    // Note: stop_reason === 'tool_use' is unreliable -- it's not always set correctly
    message.message.content.some(_ => _.type === 'tool_use')  // 检查内容中是否包含tool_use类型的块
  )
}
```

**原理**：通过检查消息类型是否为 `assistant` 且内容中包含 `tool_use` 类型的块，来识别工具使用请求。

**优势**：灵活识别工具使用请求，不依赖于不可靠的 `stop_reason` 字段。

#### 3.2.2 工具结果消息识别

```typescript
export function isToolUseResultMessage(
  message: Message,  // 消息对象
): message is ToolUseResultMessage {
  return (

    ((Array.isArray(message.message.content) &&  // 检查内容是否为数组
      message.message.content[0]?.type === 'tool_result') ||  // 检查第一个内容块是否为tool_result类型
      Boolean(message.toolUseResult))  // 或检查是否存在toolUseResult属性
  )
}
```

**原理**：通过检查消息类型是否为 `user` 且内容中包含 `tool_result` 类型的块，或存在 `toolUseResult` 属性，来识别工具结果消息。

**优势**：支持多种工具结果表示方式，提高系统的兼容性。

#### 3.2.3 消息重新排序

```typescript
export function reorderMessagesInUI(
  messages: (
    | NormalizedUserMessage
    | NormalizedAssistantMessage
    | AttachmentMessage
    | SystemMessage
  )[],  // 消息数组
  syntheticStreamingToolUseMessages: NormalizedAssistantMessage[],  // 合成的流式工具使用消息
): (
  | NormalizedUserMessage
  | NormalizedAssistantMessage
  | AttachmentMessage
  | SystemMessage
)[] {
  // 按工具使用ID映射相关消息
  const toolUseGroups = new Map<
    string,
    {
      toolUse: ToolUseRequestMessage | null  // 工具使用消息
      preHooks: AttachmentMessage[]  // 前置钩子消息
      toolResult: NormalizedUserMessage | null  // 工具结果消息
      postHooks: AttachmentMessage[]  // 后置钩子消息
    }
  >()

  // 第一遍：按工具使用ID分组消息
  for (const message of messages) {
    // 处理工具使用消息
    if (isToolUseRequestMessage(message)) {
      const toolUseID = message.message.content[0]?.id
      if (toolUseID) {
        if (!toolUseGroups.has(toolUseID)) {
          toolUseGroups.set(toolUseID, {
            toolUse: null,
            preHooks: [],
            toolResult: null,
            postHooks: [],
          })
        }
        toolUseGroups.get(toolUseID)!.toolUse = message
      }
      continue
    }

    // 处理前置钩子消息
    if (
      isHookAttachmentMessage(message) &&
      message.attachment.hookEvent === 'PreToolUse'
    ) {
      const toolUseID = message.attachment.toolUseID
      if (!toolUseGroups.has(toolUseID)) {
        toolUseGroups.set(toolUseID, {
          toolUse: null,
          preHooks: [],
          toolResult: null,
          postHooks: [],
        })
      }
      toolUseGroups.get(toolUseID)!.preHooks.push(message)
      continue
    }

    // 处理工具结果消息
    if (
      message.type === 'user' &&
      message.message.content[0]?.type === 'tool_result'
    ) {
      const toolUseID = message.message.content[0].tool_use_id
      if (!toolUseGroups.has(toolUseID)) {
        toolUseGroups.set(toolUseID, {
          toolUse: null,
          preHooks: [],
          toolResult: null,
          postHooks: [],
        })
      }
      toolUseGroups.get(toolUseID)!.toolResult = message
      continue
    }

    // 处理后置钩子消息
    if (
      isHookAttachmentMessage(message) &&
      message.attachment.hookEvent === 'PostToolUse'
    ) {
      const toolUseID = message.attachment.toolUseID
      if (!toolUseGroups.has(toolUseID)) {
        toolUseGroups.set(toolUseID, {
          toolUse: null,
          preHooks: [],
          toolResult: null,
          postHooks: [],
        })
      }
      toolUseGroups.get(toolUseID)!.postHooks.push(message)
      continue
    }
  }

  // 第二遍：按正确顺序重构消息列表
  const result: (
    | NormalizedUserMessage
    | NormalizedAssistantMessage
    | AttachmentMessage
    | SystemMessage
  )[] = []
  const processedToolUses = new Set<string>()  // 已处理的工具使用ID

  for (const message of messages) {
    // 检查是否为工具使用消息
    if (isToolUseRequestMessage(message)) {
      const toolUseID = message.message.content[0]?.id
      if (toolUseID && !processedToolUses.has(toolUseID)) {
        processedToolUses.add(toolUseID)
        const group = toolUseGroups.get(toolUseID)
        if (group && group.toolUse) {
          // 按顺序输出：工具使用 → 前置钩子 → 工具结果 → 后置钩子
          result.push(group.toolUse)
          result.push(...group.preHooks)
          if (group.toolResult) {
            result.push(group.toolResult)
          }
          result.push(...group.postHooks)
        }
      }
      continue
    }

    // 检查是否为工具使用组的一部分
    if (
      isHookAttachmentMessage(message) &&
      (message.attachment.hookEvent === 'PreToolUse' ||
        message.attachment.hookEvent === 'PostToolUse')
    ) {
      // 跳过 - 已在工具使用组中处理
      continue
    }

    if (
      message.type === 'user' &&
      message.message.content[0]?.type === 'tool_result'
    ) {
      // 跳过 - 已在工具使用组中处理
      continue
    }

    // 处理API错误消息（只保留最后一个）
    if (message.type === 'system' && message.subtype === 'api_error') {
      const last = result.at(-1)
      if (last?.type === 'system' && last.subtype === 'api_error') {
        result[result.length - 1] = message
      } else {
        result.push(message)
      }
      continue
    }

    // 添加独立消息
    result.push(message)
  }

  // 添加合成的流式工具使用消息
  for (const message of syntheticStreamingToolUseMessages) {
    result.push(message)
  }

  // 过滤只保留最后一个API错误消息
  const last = result.at(-1)
  return result.filter(
    _ => _.type !== 'system' || _.subtype !== 'api_error' || _ === last,
  )
}
```

**原理**：
1. 首先按工具使用ID对消息进行分组，包含工具使用、前置钩子、工具结果和后置钩子
2. 然后按正确的顺序重构消息列表：工具使用 → 前置钩子 → 工具结果 → 后置钩子
3. 最后处理独立消息和合成消息

**优势**：
- 确保工具使用和结果消息相邻显示，提高用户体验
- 正确处理工具执行的整个生命周期，包括钩子
- 保持消息的逻辑顺序，便于理解工具执行流程

## 4. 工具注册机制

### 4.1 静态工具注册

Claude Code 的工具注册采用静态方式，通过以下步骤实现：

1. **工具定义**：每个工具在单独的文件中定义，如 `BashTool.ts`、`FileReadTool.ts` 等
2. **工具导入**：在 `tools.ts` 中集中导入所有工具
3. **工具集合管理**：通过 `getAllBaseTools()` 函数返回所有可能可用的工具列表

#### 4.2.2 工具池组装

```typescript
export function assembleToolPool(
  permissionContext: ToolPermissionContext,
  mcpTools: Tools,
): Tools {
  const builtInTools = getTools(permissionContext)

  // Filter out MCP tools that are in the deny list
  const allowedMcpTools = filterToolsByDenyRules(mcpTools, permissionContext)

  // Sort each partition for prompt-cache stability, keeping built-ins as a
  // contiguous prefix. The server's claude_code_system_cache_policy places a
  // global cache breakpoint after the last prefix-matched built-in tool; a flat
  // sort would interleave MCP tools into built-ins and invalidate all downstream
  // cache keys whenever an MCP tool sorts between existing built-ins. uniqBy
  // preserves insertion order, so built-ins win on name conflict.
  // Avoid Array.toSorted (Node 20+) — we support Node 18. builtInTools is
  // readonly so copy-then-sort; allowedMcpTools is a fresh .filter() result.
  const byName = (a: Tool, b: Tool) => a.name.localeCompare(b.name)
  return uniqBy(
    [...builtInTools].sort(byName).concat(allowedMcpTools.sort(byName)),
    'name',
  )
}
```

**原理**：`assembleToolPool()` 函数将内置工具和 MCP 工具组合成一个完整的工具池。

**优势**：
- 支持 MCP 工具的集成
- 确保内置工具和 MCP 工具的一致性
- 按名称排序，提高提示缓存的稳定性
- 处理工具名称冲突，内置工具优先

### 4.3 工具注册机制的特点

1. **静态注册**：工具通过代码导入和函数调用来注册，而不是通过动态的注册函数
2. **环境感知**：工具的可用性受环境变量和特性标志控制
3. **权限过滤**：根据权限上下文过滤工具，确保安全
4. **MCP 支持**：支持通过 MCP 协议添加外部工具
5. **工具别名**：支持工具别名，便于向后兼容
6. **工具池组装**：通过 `assembleToolPool()` 函数组合内置工具和 MCP 工具

### 4.4 优势与局限性

#### 优势

1. **性能优化**：静态注册方式在运行时不需要动态查找和注册工具，性能较好
2. **类型安全**：TypeScript 类型系统确保工具接口的一致性
3. **可控性**：工具集合在编译时就确定，便于管理和测试
4. **灵活性**：通过环境变量和特性标志控制工具的可用性

#### 局限性

1. **扩展性**：添加新工具需要修改代码，不能在运行时动态添加
2. **配置复杂度**：工具的可用性依赖于环境变量和特性标志，配置较为复杂
3. **维护成本**：随着工具数量的增加，`getAllBaseTools()` 函数会变得越来越长

## 5. 工具定义与实现

### 5.1 工具接口

```typescript
export type Tool<
  Input extends AnyObject = AnyObject,
  Output = unknown,
  P extends ToolProgressData = ToolProgressData,
> = {
  /**
   * Optional aliases for backwards compatibility when a tool is renamed.
   * The tool can be looked up by any of these names in addition to its primary name.
   */
  aliases?: string[]
  /**
   * One-line capability phrase used by ToolSearch for keyword matching.
   * Helps the model find this tool via keyword search when it's deferred.
   * 3–10 words, no trailing period.
   * Prefer terms not already in the tool name (e.g. 'jupyter' for NotebookEdit).
   */
  searchHint?: string
  call(
    args: z.infer<Input>,
    context: ToolUseContext,
    canUseTool: CanUseToolFn,
    parentMessage: AssistantMessage,
    onProgress?: ToolCallProgress<P>,
  ): Promise<ToolResult<Output>>
  description(
    input: z.infer<Input>,
    options: {
      isNonInteractiveSession: boolean
      toolPermissionContext: ToolPermissionContext
      tools: Tools
    },
  ): Promise<string>
  readonly inputSchema: Input
  // Type for MCP tools that can specify their input schema directly in JSON Schema format
  // rather than converting from Zod schema
  readonly inputJSONSchema?: ToolInputJSONSchema
  // Optional because TungstenTool doesn't define this. TODO: Make it required.
  // When we do that, we can also go through and make this a bit more type-safe.
  outputSchema?: z.ZodType<unknown>
  inputsEquivalent?(a: z.infer<Input>, b: z.infer<Input>): boolean
  isConcurrencySafe(input: z.infer<Input>): boolean
  isEnabled(): boolean
  isReadOnly(input: z.infer<Input>): boolean
  /** Defaults to false. Only set when the tool performs irreversible operations (delete, overwrite, send). */
  isDestructive?(input: z.infer<Input>): boolean
  /**
   * What should happen when the user submits a new message while this tool
   * is running.
   *
   * - `'cancel'` — stop the tool and discard its result
   * - `'block'`  — keep running; the new message waits
   *
   * Defaults to `'block'` when not implemented.
   */
  interruptBehavior?(): 'cancel' | 'block'
  /**
   * Returns information about whether this tool use is a search or read operation
   * that should be collapsed into a condensed display in the UI. Examples include
   * file searching (Grep, Glob), file reading (Read), and bash commands like find,
   * grep, wc, etc.
   *
   * Returns an object indicating whether the operation is a search or read operation:
   * - `isSearch: true` for search operations (grep, find, glob patterns)
   * - `isRead: true` for read operations (cat, head, tail, file read)
   * - `isList: true` for directory-listing operations (ls, tree, du)
   * - All can be false if the operation shouldn't be collapsed
   */
  isSearchOrReadCommand?(input: z.infer<Input>): {
    isSearch: boolean
```

## 7. 工具执行与结果处理

### 7.1 工具执行

工具执行的核心是 `call` 方法，它接收工具参数、上下文、权限检查函数等，执行具体的操作，并返回结果。

**原理**：
1. 工具接收输入参数
2. 执行具体的操作（如文件读写、命令执行等）
3. 处理执行结果
4. 返回标准化的工具结果

**优势**：
- 统一的执行接口，便于工具的开发和管理
- 支持异步执行，适合处理耗时操作
- 支持进度报告，提供更好的用户体验

### 7.2 工具结果处理

工具执行完成后，系统会处理工具结果，生成工具结果消息，并返回给模型。

**原理**：
1. 工具执行返回 `ToolResult` 对象
2. 系统调用 `mapToolResultToToolResultBlockParam` 方法，将工具结果转换为标准的工具结果块
3. 生成工具结果消息
4. 将工具结果消息添加到对话中

**优势**：
- 标准化的结果处理流程，确保工具结果的一致性
- 支持丰富的结果类型，满足不同工具的需求
- 便于模型理解和处理工具结果

## 8. 工具权限系统

### 8.1 权限检查流程

工具执行前，系统会进行权限检查，确保用户有权限执行该工具。

**原理**：
1. 工具调用 `validateInput` 方法，验证输入参数
2. 系统调用 `checkPermissions` 方法，检查用户权限
3. 根据权限检查结果，决定是否执行工具

**优势**：
- 确保系统的安全性，防止未授权的操作
- 支持细粒度的权限控制，根据工具和参数进行权限检查
- 提供统一的权限检查接口，便于工具的开发和管理
